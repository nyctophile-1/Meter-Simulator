# ESW pull contract

The HES command enum calls command 66 `GetESWF`, and its custom request selector is GetWithoutData (1). The checked PostgreSQL configuration includes 66 in generic custom pull. Templates 88 and 93 use Misc templates 27 and 28; neither has a GetESWF override in the checked metadata. The Common fallback maps this command to `0.0.94.91.18.255` (ESW-1). The D1 XML separately declares `0.0.94.91.26.255` as ESWF. These objects must not be swapped or merged.

The simulator's custom decoder previously rejected command 66. It now accepts that read selector and uses a bounded, isolated DLMS association over the requested meter's state to read its clock and ESW-1. The response follows the HES generic ESW profile: discriminator 5, configured custom header/magic, current RTC, bit-string tag 4, length 128, and 16 bytes in MSB-first order. It echoes the request frame and meter serial. The XML filter is not modified. No meter index, template ID or category layout is hardcoded into this handler.

This implements the checked HES contract, not a claim that the command name correctly describes every vendor's ESWF object. A future template with a different command mapping must be verified before claiming coverage for it. Direct DLMS reads of `.18` and `.26` remain separate operations.

Source references: `vayu-common/CrystalHES.Common/Helpers/CustomPullCommandPayload.cs`, `Helpers/Functions.cs`, `Helpers/GenericHelpers.cs`, `CustomGenericParser.cs`, and `vayu-core/CrystalHES.MQTTService/Client/MQTTSendCustomCommandClient.cs`. The focused simulator custom-profile suite passes 19 cases, including response discriminator, size, all 128 bits, request frame, RTC, and invalid-selector rejection. The handler is deployed on both servers. Live command 98932984 completed in one try and persisted row 3908521 with current RTC; all 128 returned/stored bits match deployed ESW-1 and differ from the filter.

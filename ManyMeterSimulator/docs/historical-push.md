# Historical push

Testing → Historical push sends both instantaneous and block-load data for the selected running batches. Select N days, instantaneous cadence, concurrency, record-attempt rate, MQTT publisher count and QoS, then Start. Stop cancels waits and in-flight delivery. The service survives page navigation, but runs are in memory and do not resume after a process restart.

The run freezes its UTC end time at startup. It visits capture boundaries in `[end − N days, end]` chronologically, without sending future or incomplete block intervals. Instantaneous uses the selected cadence; block load uses the batch's DLMS capture period or custom template's configured block period. Each meter/profile/time is attempted once. Completion stops the run; there is no subsequent live loop. Existing PCP/batch live traffic remains independently scheduled.

The attempt-rate limit is shared by both profiles and every selected batch, and includes skipped attempts. Concurrency bounds active workers. MQTT pools remain open for the run, with one pool per broker/transport shared by the two profiles. TCP retains per-meter source-IP binding. Records are generated lazily; no N-day payload cache is allocated. Existing DLMS meter-session memory still scales with the materialized fleet.

All production push entry points share `PushCoordinator.BuildDlms` / `DLMSServerSession.BuildPushPayloads` for DLMS, the `ResolveMqttSource` builder / `CustomPushEncoder` for custom Wirepas, and the existing TCP sender or MQTT pool for delivery. Historical mode supplies a reading timestamp to those builders. It does not maintain a separate wire encoder.

DLMS uses retained profile rows when the requested block slot exists; beyond retained history it cycles template samples on the capture grid. Instantaneous retains the model's register values with the requested reading time. These are simulated sample replays, not reconstructed historical measurements. Projection does not rewind the meter value store or change profile buffers. Custom Wirepas uses `CustomProfileDataGenerator` with the historical timestamp and configured block interval, including time-dependent cumulative energy. Ciphered DLMS is generated immediately, without caching encrypted frames.

Every push mode calls the same `AllowPushAsync` gate before delivery, including prepared stress fire, single-button, scheduled PCP/batch traffic, and historical push. The gate reads current **push** BadComm settings each attempt. Non-comm skips all delivery; bad-comm applies probabilistic loss. Historical skips advance the cursor and are not retried, leaving gaps. Changing settings affects subsequent attempts. Class membership is deterministic; individual packet losses use the existing per-exchange random policy. Repeating a run can produce different gaps.

Historical replay is accelerated by default: it applies the same loss policy without sleeping for simulated network delays. Enable **Wait for simulated network delays** to apply the configured push delay and BadComm multiplier as wall-clock waits. These waits occupy the bounded workers, so 64 workers with a 1-second average delay can attempt only about 64 records/sec regardless of the rate ceiling or CPU capacity. Other push modes retain their configured delay behavior. Global push/pull settings are unchanged. Actual MQTT acknowledgements and socket delivery are always awaited; accelerated timing does not bypass delivery guarantees. Rate, concurrency, publisher count, encoding and receiver capacity still bound throughput.

The UI separates successful records, BadComm skips, delivery failures, messages sent, and achieved records/sec. A record can require multiple transport messages. Sent means local socket completion or MQTT publish completion, not verified HES parsing or persistence. Batch/destination changes stop the run. Cancellation retains completed-message accounting. Transport failures remain visible rather than being classified as BadComm gaps.

Local tests decode historical DLMS (plain and ciphered) and custom Wirepas payloads, verify time boundaries and block cadence, preserve live values, check complete record coverage, inject partial/all BadComm loss across push entry points, exercise TCP loopback identity, and check stop/pool disposal and configuration invalidation.

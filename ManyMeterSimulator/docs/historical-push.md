# Historical push

Testing → Historical push sends both instantaneous and block-load data for the selected running batches. Select N days, instantaneous cadence, concurrency, record-attempt rate, MQTT publisher count and QoS, then Start. Stop cancels waits and in-flight delivery. The service survives page navigation, but runs are in memory and do not resume after a process restart.

The run freezes its UTC end time at startup. It visits capture boundaries in `[end − N days, end]` chronologically, without sending future or incomplete block intervals. Instantaneous uses the selected cadence; block load uses the batch's DLMS capture period or custom template's configured block period. Each meter/profile/time is attempted once. Completion stops the run; there is no subsequent live loop. Existing PCP/batch live traffic remains independently scheduled.

Historical push runs unthrottled by default (`RecordsPerSecond = 0`): there is no application rate timer or records/sec ceiling. **Limit record attempts per second** optionally enables a shared budget across both profiles and every selected batch, including skipped attempts. The slider and exact-value field support 100–300,000 record attempts/sec and can be changed while connecting or sending, without restarting. Turn the limit off to return to unthrottled replay. Pending rate waits observe updates within the limiter polling interval (up to 10 ms plus scheduling); already admitted records may finish at the previous rate. This is a record budget, not an MQTT message budget: one record can produce multiple messages. Defaults are 256 concurrent workers and 256 MQTT publishers per broker/transport, keeping one outstanding publish per connection. These bounded in-flight operations await real transport completion and prevent an unbounded queue; they do not impose a timed rate. MQTT pools remain open for the run and are shared by the two profiles. TCP retains per-meter source-IP binding. Records are generated lazily; no N-day payload cache is allocated. Existing DLMS meter-session memory still scales with the materialized fleet.

All production push entry points share `PushCoordinator.BuildDlms` / `DLMSServerSession.BuildPushPayloads` for DLMS, the `ResolveMqttSource` builder / `CustomPushEncoder` for custom Wirepas, and the existing TCP sender or MQTT pool for delivery. Historical mode supplies a reading timestamp to those builders. It does not maintain a separate wire encoder.

DLMS uses retained profile rows when the requested block slot exists; beyond retained history it cycles template samples on the capture grid. Instantaneous retains the model's register values with the requested reading time. These are simulated sample replays, not reconstructed historical measurements. Projection does not rewind the meter value store or change profile buffers. Custom Wirepas uses `CustomProfileDataGenerator` with the historical timestamp and configured block interval, including time-dependent cumulative energy. Ciphered DLMS is generated immediately, without caching encrypted frames.

MQTT and TCP stress tests (live, prepared Fire, and continuous loops) bypass simulated network delays, NonComm skips, and BadComm failures. Historical push bypasses simulated delays while retaining live NonComm skips and BadComm loss; skipped slots advance without retry. Normal single-button and scheduled PCP/batch traffic continue to apply the current push impairment settings. Load tests do not modify the saved push/pull settings.

Historical replay never waits for simulated network delays. Actual MQTT acknowledgements and socket delivery are still awaited. Explicit rate limits, concurrency, publisher count, encoding and receiver capacity continue to bound throughput.

The UI separates successful records, BadComm/NonComm skips, delivery failures, messages sent, and achieved records/sec. A record can require multiple transport messages. Sent means local socket completion or MQTT publish completion, not verified HES parsing or persistence. Batch/destination changes stop the run. Cancellation retains completed-message accounting. Transport failures remain visible rather than being classified as BadComm gaps.

Local tests decode historical DLMS (plain and ciphered) and custom Wirepas payloads, verify time boundaries and block cadence, preserve live values, check complete record coverage, verify stress impairment bypass, historical loss without delay, and normal traffic impairments, exercise TCP loopback identity, and check stop/pool disposal and configuration invalidation.

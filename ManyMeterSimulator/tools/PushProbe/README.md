# Bounded push verification

This diagnostic generator calls the production DLMS session and MQTT codecs, or the existing custom encoder, and writes payloads with SHA-256 hashes. It does not connect to a broker. It does not stand in for `PushCoordinator` or HES integration tests. Unsupported selections are recorded as errors, never counted as successful sends.

Build with `dotnet build PushProbe.csproj -c Release`, then run the generated DLL with one JSON configuration path. Configuration properties are `Template` (absolute XML path), `Index` (provisioned meter index), `Nic`, `HesTemplateId`, `MagicNumber`, `Gateway`, `Sink`, `Ciphering`, `Output` (artifact directory), and `Profiles` (explicit profile keys). Obtain identities, template mappings, magic numbers and transport settings from the intended environment before using the generated artifacts.

DLMS profile keys are the session's advertised PushSetup logical names and work independently of NIC type. Custom keys are `custom:instant`, `custom:block`, `custom:daily`, `custom:bill`, `custom:esw`, `custom:rtc`, and `custom:event:{voltage,current,power,transaction,other,nonrollover,control}`. The saved key `custom:93:daily` remains a compatibility alias. RTC push applies only to custom Wirepas.

Custom generation uses the production metadata encoder. Provide `DataModelDirectory` containing the HES `MeterTemplate.csv`, `MeterTemplateDetail.csv` and `MagicNumberMapping.csv` exports, `MeterCategory` (`1P`, `3P` or `CT`), and the registered `MagicNumber` if the template has multiple mappings. Events also require `EventsWithPowerProfile` from the HES setting and an `EventIds` dictionary mapping each selected custom event key to an ID allowed for that category. There is no default event ID. `ResponseTimestampOffsetMinutes` defaults to 330 and must match the receiver's custom date convention. Only the verified 12-byte transport/11-byte profile header combination is supported. Unsupported or incomplete metadata fails explicitly; arbitrary fixture template IDs do not establish D2/D3 runtime coverage. Credentials do not belong in this configuration.

The output `generated.json` records source template hash, generation time, each selected profile, topic, payload path and payload hash. Generating a packet proves neither broker delivery nor HES parsing/persistence. Keep normal-topic results distinct from a diagnostic replay to a consumer-specific topic, and compare RTC/values against the original generated packet time rather than replay time.

Set `Routing` to `true` to generate one empty-payload fakerouting artifact using the production `NicTopics.FakeRouting` mapping. Set `Profiles` to an empty array for routing only. A routing check must compare the existing route and last-communication timestamp before and after the publish. HES preserves an existing gateway/sink; an RF node without a route requires real gateway/sink routing and cannot be initialized by an empty keepalive alone. Check for concurrent simulator routing traffic before attributing a timestamp change to the probe.

Optional `Reads` selects bounded local DLMS read exchanges. Each entry has `Label`, `LogicalName`, `Attribute` (default 2), and optional `Start`/`Count` for one or two profile rows. Set `Profiles` to an empty array for reads only. `local-pull.json` distinguishes a nonempty response, an empty response and a protocol failure. Reads use a fresh public association (client 16), with limits of 128 exchanges and 1 MiB. These results do not prove HES command correlation, authenticated HES reads, MQTT/TCP reachability, or persistence. An access denial on this public association is not proof that the HES association also fails.

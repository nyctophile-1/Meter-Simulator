# TCP stress concurrency and connection lifetime

Testing > TCP stress defaults to concurrency 0 (unlimited), no meter limit, whole-pass waves, no wave pause and prepared-memory budget 0 (unlimited). Positive concurrency and memory values remain optional operator controls; the former 1024/16384 caps are removed. No application concurrency admission ceiling is applied when concurrency is 0. Actual parallel sockets depend on the fleet, payload generation, scheduler, network and host resources. CPU-only preparation uses available processors; it opens no sockets.

The TCP stress and historical TCP UI default to a 15-second maximum wait for HES closure after sending. MAYA does not send FIN first in this mode. HES's current framed listener closes after about 10 seconds waiting for another frame. A peer can close earlier. Set wait to 0 for immediate send/close; this is also the backward-compatible request default for old persisted plans/checkpoints and normal scheduled traffic.

A wait timeout closes locally without replaying the written payload. Stop cancels outstanding connect, write and peer-close waits. Stress and historical runs account packets when socket writes finish. Post-write waits belong to the run and release send workers immediately. Stop cancels those waits without turning already-counted writes into send failures. Normal run completion drains the remaining sockets; disposal cancels and drains them. Closure does not acknowledge database persistence.

The connection panel counts all TCP push sockets in the MAYA process, including background traffic. It separates connecting/active/peak sockets, connections opened per second, local payload writes per second, connection failures, peer EOF, local wait expiry and close/read errors. Active sockets exclude disposed sockets still retained in kernel closing states; counters and peaks reset on service restart.

Historical replay retains chronological IP/LS write ordering. A timestamp advances when its packet writes settle. TCP stress loops can start their next pass while earlier sockets remain held, but both paths must wait before opening another connection for the same meter. Unlimited concurrency removes the old per-timestamp dispatch chunk ceiling and the 2048-completion checkpoint restriction. Continue retains a saved run's explicit settings. A new historical run defaults to concurrency 0 and rate limiting off, even when an old checkpoint exists. MQTT publisher pools remain separate transport controls.

The singleton TCP sender enforces one live push connection per meter across all runs, destinations and background traffic. The meter's slot covers connect, write and any post-write hold, and is released only after socket disposal. Cancellation while waiting opens no socket; connect/write failures, peer EOF, deadline and Stop release the slot. No fleet-wide concurrency ceiling is introduced. Meter source IPs remain unchanged and source ports remain OS-assigned; the application does not force reuse of a closing TCP endpoint or cap AWS's retained connection-tracking state.

For one push per connection, 50,000 meters with a ten-second connection lifecycle can sustain at most 5,000 pushes/sec; at fifteen seconds this is about 3,333/sec. More meters or shorter actual lifetimes are needed for higher connection rates. These are capacity calculations, not measured HES persistence rates. Socket regression tests cover cross-run exclusion, unrelated-meter progress, cancellation, connection failure, EOF, deadlines, stress cycles and historical IP/LS frames.

No OS limits, VM capacity, traffic start or HES settings are changed by this release. A healthy deployment is not a throughput benchmark.
